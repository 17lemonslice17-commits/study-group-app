# 스터디 모임 관리 서비스 기획서

## 1. 서비스 개요
- 서비스명: 모임장
- 한 줄 소개: 스터디/소모임을 만들고, 일정을 관리하고, 출석을 체크하는 웹 서비스
- 만들게 된 배경: 재학 중 여러 팀 프로젝트에 참여하게 되었는데, 그럴 때마다 실질적인 사안을 논의하는 회의 시간보다 함께 일정을 조율하고, 출석 인원을 점검하는 데 상당 시간을 할애하게 됨. 그런 일이 반복되다 보니 비효율적이라 느끼며, 학교 외부의 일반인들도 스터디나 소모임에서 같은 불편을 겪고 있으리라 생각해서 만들게 됨.

## 2. 타겟 사용자
- 주 사용자: 팀 프로젝트를 진행중인 대학생, 소규모 스터디 팀
- 사용자가 겪는 불편함: 시간 조율이 시각적으로 명시적이지 않아서 서로의 가능한 시간을 파악하기가 어려움, 카톡방에 공지하더라도 사람마다 확인하는 시간이 달라서 동시에 조율하기 쉽지 않음, 출석 체크 과정에 회의 시간을 할애하게 됨

## 3. 핵심 기능 (MVP 기준 우선순위)
| 우선순위 | 기능 | 설명 |
|---|---|---|
| P0 | 회원가입/로그인 | 이메일 기반 인증 |
| P0 | 모임 생성/참여 | 모임장이 모임 개설, 초대코드로 멤버 참여 |
| P0 | 일정 등록/조회 | 모임별 일정 캘린더 |
| P1 | 게시판 | 공지/자유글 + 댓글 |
| P1 | 출석 체크 | 일정별 참석 여부 기록 |
| P2 | 알림 | (추후 확장) |

## 4. 화면 흐름 (User Flow)
로그인 -> 내 모임 목록 -> 모임 선택 -> [일정 탭 / 게시판 탭] -> 상세 화면

## 5. MVP 범위

### 포함 범위
이번 MVP에서는 스터디 모임을 만들고 참여한 뒤, 모임의 일정과 게시판을 관리할 수 있는 핵심 기능까지만 구현한다.

- 회원가입/로그인

  - 이메일과 비밀번호를 이용한 회원가입 및 로그인
  - 로그인한 사용자의 기본 프로필 관리

- 모임 관리

  - 모임장이 새로운 스터디 모임 생성
  - 모임 이름, 소개, 모임장 정보 등록
  - 초대코드를 이용한 모임 참여
  - 내가 참여한 모임 목록 조회

- 일정 관리

  - 모임장이 스터디 일정 등록
  - 일정의 날짜, 시간, 장소, 설명 등록
  - 모임별 일정 목록 및 캘린더 조회

- 게시판

  - 공지글 및 자유글 작성/조회
  - 게시글 수정 및 삭제
  - 댓글 작성

- 출석 체크

  - 일정별 참석/불참 여부 기록
  - 모임장이 멤버들의 출석 현황 조회

### 제외 범위

MVP에서는 개발 범위를 최소화하기 위해 다음 기능은 구현하지 않는다.

- 카카오톡, 구글 등 소셜 로그인
- 실시간 채팅
- 푸시 알림 및 문자/이메일 알림
- 파일 및 이미지 업로드
- 복잡한 권한 관리
- 일정 자동 반복 등록
- 출석 통계 및 그래프
- 관리자용 별도 페이지
- 모바일 앱(iOS/Android)
- 결제 및 유료 기능

### MVP 완료 기준

다음 시나리오가 정상적으로 동작하면 MVP 개발 완료로 판단한다.

> 사용자가 회원가입 및 로그인 → 모임 생성 → 다른 사용자가 초대코드로 참여 → 모임장이 스터디 일정 등록 → 멤버가 일정을 확인하고 출석 여부 기록 → 모임 게시판에서 공지 및 댓글 작성

MVP 이후에는 실제 사용자 피드백을 바탕으로 알림, 채팅, 출석 통계 등의 기능을 우선순위에 따라 추가한다.

## 6. ERD (테이블 설계)

- users (id, email, password_hash, nickname)
- groups (id, name, owner_id, invite_code)
- group_members (id, group_id, user_id, role)
- schedules (id, group_id, title, start_at)
- attendance (id, schedule_id, user_id, checked)
- posts (id, group_id, author_id, title, content)
- comments (id, post_id, author_id, content)

관계:
- users 1:N group_members N:1 groups (다대다 연결 테이블)
- groups 1:N schedules
- schedules 1:N attendance, users 1:N attendance
- groups 1:N posts, posts 1:N comments
